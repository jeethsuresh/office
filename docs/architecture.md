# Architecture

Spreadsheets and cross-block references extend the same shared model and transports. `DocumentAPI` supplies typed cell/record transactions and changeset subscriptions; `OfficeData` composes target resolution, observe-only foreign sessions, and versioned formula-worker results. Spreadsheet coordinates and slide positions are views over persistent IDs and placement logs. Tiptap heading IDs are assigned after its active transaction, while inline reference nodes render current target labels and values. Glide's overlay portal is inside the stable fullscreen host. Production builds precache the worker and lazy grid editors for offline reload. See [spreadsheets and references](spreadsheets-and-references.md) for API and calculation details.

## Runtime

Electron starts `office-server` on a loopback port chosen on the first launch and retained in `desktop-port` and loads the UI from that same server. The Go process announces readiness as one JSON stdout line. In development, Electron starts Go on port 4317 and loads Vite on 5174; Vite proxies `/api` including WebSockets to Go. In production, Go serves built web assets and the APIs from one origin. A standalone browser/mobile session uses exactly the same modules.

The desktop renderer has sandboxing and context isolation enabled, no Node integration, and a minimal preload exposing desktop/platform information. External web links open in the default browser. The shell owns backend shutdown and reports unexpected process exits. No editor depends on Electron.

## Durable state

A workspace directory contains `workspace.json` and `journals/<document-id>.ylog`. Workspace metadata includes a stable workspace ID, folders, and document names/created/updated timestamps. A stable workspace ID also namespaces IndexedDB within that origin. Electron retains the same origin between launches because IndexedDB itself is origin-scoped. Metadata writes use a synced temporary file followed by atomic rename. Go holds a mutex for catalog mutations and rejects folder cycles and deletion of nonempty folders.

Content journals store big-endian length-prefixed Yjs updates. Each record is synced before its WebSocket acknowledgement. Incomplete final records after interrupted writes are truncated on reopening. Complete malformed records are reported, not silently discarded. The welcome snapshot is embedded in Go and installed once per new workspace; clients never race to seed a document.

## Shared schema

`Y.Doc.getArray('blocks')` holds `Y.Map` block records with `id`, `kind`, and `title`.

`Y.Doc.getArray('blockMoves')` stores ordered, immutable `{block, before, after}` move operations. `orderedBlocks()` replays them over the existing records, so a reorder never deletes, clones, or reinserts integrated rich-text/canvas types. Concurrent moves have a deterministic CRDT order, and concurrent content edits retain their original targets. Missing block IDs are ignored; a missing destination falls back to the surviving neighbor or the appropriate edge. New insertions after a reorder also record their anchored placement. Structural undo covers both the block array and the move array, preserving remote operations. Existing documents with no move history retain their original order. The move log shares the journal's future compaction needs.

- Doc: `content: Y.XmlFragment` bound directly to Tiptap/ProseMirror.
- Canvas: `shapes: Y.Map<Y.Map>`; each shape field is a separately merged register. All clients can edit any object simultaneously.
- Slides: `slides: Y.Array<Y.Map>`; each slide has an ID, layout ID, shared title/subtitle (`Y.Text`), `contentKind`, a rich-text fragment, and a shape map.

A content slide retains both content forms and switches the visible editor without clearing either. Each rich-text editor owns its own collaboration history. Canvas undo targets its shape map and only local mutation origins. Block and slide structural undo targets its own collection. Remote mutations do not enter those local undo stacks.

## UI boundaries

The Office logo opens `WorkspaceBrowser`, a catalog view independent of document sessions. Hash routes identify either a document or a workspace folder; browser history and breadcrumbs navigate between them. The browser reads the existing workspace metadata, reuses `WorkspaceDialog` mutations, and persists list/icon and sort preferences locally. Folder navigation clears the local search filter. Returning to a document reconnects its session and preserves CRDT content. `Presence` reads live awareness states and displays every name on hover/focus/tap, including avatar overflow.

`DocEditor` accepts a fragment and session. `CanvasEditor` accepts a shape map, session, and unique scope ID for cursors. Both support compact and read-only rendering. They can be used as document blocks or nested inside a slide layout. `SlidesEditor` owns horizontal navigation and presentation; it delegates rendering to the layout registry. Shell modules own the folder tree, document navigator, metadata forms, minimap, and block insertion.

Block navigation selects a mounted block inside a clipped grid viewport. Block sections use `display: contents` so all editor wrappers share one grid cell, each containing its own attached header and editor body. `useBlockMotion` derives the target wrapper height from the viewport and reserved end spaces, then positions surfaces relative to the selected block. The previous surface's bottom and next surface's top remain visible. Neighboring headers become full-width navigation buttons; flex order places the previous header at its bottom edge, while the next stays at its top edge. Their editing actions stay mounted but hidden/inert, and inactive editor bodies remain inert and hidden from assistive technology. Farther headers are also inert. Farther surfaces are visually hidden except during a 420ms navigation transition. Explicit navigation retargets the relative positions without remounting editors or scrolling an ancestor; reduced motion, initial load, structural changes, and fullscreen selection use immediate positioning. Relative offsets avoid creating a transformed containing block for fixed fullscreen editors, and boundary insertion occupies the empty neighboring space. Slide navigation uses mandatory horizontal CSS snapping, explicit controls, and a scrollend listener with a debounce fallback to update selection/presence after a gesture settles. Inactive cards are inert so tabbing cannot navigate sideways. Notes contain vertical overflow and allow horizontal gestures to chain into the slide track; a non-passive canvas wheel listener owns pan/zoom gestures. Canvas zoom remains local view state and is displayed between the rail's zoom buttons; the former footer is removed, including embedded canvases.

New-slide and carousel navigation use native smooth scrolling, respecting reduced-motion preferences. Carousel dots are real buttons with current-slide state, and their own horizontal viewport keeps the active dot visible. Fullscreen selection and geometry alignment still use immediate positioning to preserve the stable host.

`useMinimapMenu` opens a block-specific deletion menu from a context click, keyboard menu key, or a 550ms touch hold. Movement cancels the hold; a completed hold cancels pending dragging and suppresses its navigation click. Menus sit beside the map, stay within viewport bounds, focus their action, and close on Escape, outside interaction, or scrolling. They reuse the document confirmation and structural undo, including from expanded fullscreen. A slide marker targets its containing block. Long-deck rows defer recentering while their menu is open so focusing the action cannot dismiss it through a scroll event. Slide navigation remains in the carousel and minimap; the left rail contains editing/presentation controls.

The minimap fills its available track height with one equal-weight section per block, reserving a usable minimum and scrolling the track for very large documents. Slide rows stay inside one deck outline. `MinimapSlides` shows all rows for decks of up to five slides; longer decks use a five-row scroll viewport sized by `ResizeObserver`. Two empty rows at each end keep even the first and last slide centered. Hovering the edge arrows animates scrolling; wheel, touch, arrow taps, and keyboard controls browse the remaining rows without changing selection. Pointer/focus departure recenters the selected row, and selecting a slide recenters it immediately. Tooltips wrap complete titles outside the narrow map. The document viewport can shrink below editor intrinsic widths, keeping the map within desktop and mobile bounds.

At 1200px and above, the map widens and `BlockPreview` renders bounded SVG summaries of rich-text structure and canvas geometry, with slide previews inside their existing rows. The summaries read shared data directly and update with the parent’s deep Yjs subscription; they do not mount additional editors. Expanded fullscreen maps can extend beyond the original controls rail without clipping. The minimap provides block insertion, deletion, and structural undo; headers also expose confirmed whole-block deletion. Insertion resolves the selected anchor ID against the current block order when the modal commits, accommodating concurrent changes; if that anchor was removed, insertion falls back to the end. The beginning/end entry points are retained.

`useMinimapDrag` captures title/number pointer gestures, finds insertion boundaries, scrolls the map near its edges, and supports Escape cancellation. Keyboard moves share the same model operation. Gap buttons pass the neighboring block ID to the insertion modal, including in expanded fullscreen. Tooltip placement uses the actual map rectangle to choose the adjacent side and available width. Fullscreen follows the active block after an insertion and gives top-layer dialogs and ongoing drags Escape priority.

`shared/Fullscreen.tsx` uses one stable document host for native fullscreen and a registry of mounted editor elements. Selection changes promote the existing editor subtree without changing the native host or opening another fullscreen Space; unsupported browsers use a fixed viewport fallback. `EditorTools` separates its scrolling tools from the pinned expand/exit footer. `FullscreenNavigator` flattens the document navigation model into a compact previous/current/next preview, then reuses the complete `Minimap` when expanded over the controls. Its expand/collapse button remains anchored above X so hover expansion cannot replace a pending click with a slide marker. Background siblings become inert, keyboard focus stays inside the editor, Escape gives nested dialogs priority, and exiting restores focus/scroll positions. Electron exposes one bounded IPC operation to wait for the native fullscreen transition: macOS may still be animating a fullscreen Space after Chromium resolves `requestFullscreen`, so an early Escape/X is queued until `enter-full-screen` completes.

`BlockActions` portals each root editor's undo/redo, whole-block deletion, and download controls into its block header; fullscreen returns them to that editor's rail without remounting the editor. Selected-element deletion stays in the left tools. The header retains the type icon/color, copy control, backlinks, and block update time; the old document caption row is removed. `trackBlockUpdates` observes authored local transactions and records each client's time under a separate CRDT clock key. The displayed time is the maximum clock plus the creation baseline, so an older offline edit cannot overwrite a later timestamp. Clock writes are outside content undo scopes, and remote replay/heading-ID migrations do not restamp content. Legacy blocks with no recorded time display an unknown time until their next edit. Exports are Markdown, SVG, calculated-value CSV, and Office slide JSON.

`BlockHeader` measures its own width with `ResizeObserver`. Below 760px, copy stays inline while the remaining actions, previous/next navigation, timestamp, and backlinks occupy a bounded nonmodal popover opened by the hamburger. Wider blocks show those controls inline. The header remains one row at every width. Keyboard arrows/Home/End navigate enabled actions, Escape restores trigger focus, and outside interaction/resize/block changes/fullscreen dismiss the popover. A native DOM click listener handles editor actions rendered through portals, whose React event ancestry bypasses the header. Headers reapply their current inert state after fullscreen cleanup, keeping neighboring editing controls read-only while enabling their navigation buttons. Neither the wrapper nor header creates a stacking context above the fullscreen editor.

At document ends, insertion reserves only the button's height plus a 4px gap; other edges retain their neighboring preview space. The two insets can differ, allowing the first/last block to use the extra height and a single block to reclaim both ends. Insets follow the motion destination in the same animation frame as relative offsets. Height and top margin animate alongside block movement, while step measurement uses the destination geometry rather than an intermediate animated height.

Fullscreen also gives the minimap menu priority on Escape and stays expanded while the pointer moves to its adjacent menu. When the focused editor is deleted locally or remotely, the provider selects a surviving registered block during the layout phase, before disconnected-editor cleanup can exit the native session. Deleting the final block exits focus mode.

The mobile profile activates at 760px. It uses a drawer sidebar and narrower rails/map while preserving all editor functionality. A short-screen profile at 650px height keeps navigation pills and embedded editors usable in landscape. The same document and CRDT structures are used in both profiles.

## Add a slide layout

1. Add a component accepting `SlideProps` in `packages/ui/src/blocks/slideLayouts.tsx` or a separate file.
2. Register `{label, component}` under a stable string ID in `slideLayouts`. The layout picker and add controls derive from this registry.
3. Initialize any new shared types in `createSlide()` in `packages/model`. Use `Y.Text` for collaboratively edited text, `Y.Map` for fields, and `Y.Array` for ordered collections.
4. Keep layout state inside the shared slide record; leave viewport, selection, and tool choices local to the UI. `SlideViewport` lays out every slide at 1280 × 720 and scales the finished surface to fit. Use fixed composition units rather than viewport-dependent typography. Presentation promotes the same mounted carousel and switches its editors to read-only, preserving text wrapping and canvas view state.
5. Preserve older field names or introduce an explicit schema migration when changing persisted records.

No switch statement needs to change to register an additional slide layout.

## Deliberate MVP boundaries

- Folder/document catalog operations use server transactions rather than a CRDT and need a live connection. Their names use last-write-wins server mutations.
- The Go server relays opaque Yjs bytes. It does not interpret the editor schema, enforce content permissions, or compact journals. Very long-lived journals need compaction and quotas before large-scale hosting.
- Collaboration is one process with local disk persistence, not a replicated service. Back up the whole data directory while the server is stopped.
- Canvas has one-object selection and translation; multi-select, resizing, image/media imports, grouping, and connector attachment are future extensions. It is an original SVG editor with an Excalidraw-style workflow, not the Excalidraw engine.
- Rich text supports common Markdown, not every Markdown dialect. Slides do not export PPTX; notes export Markdown and drawings export SVG.
- Mobile is a responsive browser profile, not a native iOS/Android application. Offline editing is available after loading a document; cold loading the entire website without a server is not supplied by a service worker.
